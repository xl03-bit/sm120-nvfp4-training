# 冻结权重 FP4 接入说明

本更新增加冻结骨干专用路径，适用于推理，以及冻结骨干参与可微目标、上游仍有参数需要训练的情况。原有六种全参数训练模式及其优化器保持不变。

## 发现的问题

面向可训练权重的线性层，可能在每次前向重新编码权重，在反向再次编码转置。直接把它用于冻结骨干，会重复处理没有变化的权重。仅换成原生 FP4 矩阵乘法，也不会自动继承图重放、降低主机发射开销或压缩所有中间状态。

另外，直接捕获 Python 随机舍入计数器，可能让每次图重放使用同一随机种子。冻结权重也不等于不需要反向：上游可训练层仍可能需要穿过骨干的输入梯度。

## 如何解决

1. `pack_frozen_layers` 预先打包正向和反向使用的两个权重方向，保留 FP4 编码、尺度和 BF16 偏置，不在转换层中保留高精度主参数。
2. `save_frozen_cache` / `load_frozen_cache` 持久化编码，校验文件摘要、格式、模型版本标识及逻辑形状，读取时不重新量化。不保存可训练适配器或优化器状态。
3. `capture_frozen` 捕获固定形状的推理，或完整标量目标及反向。设备端种子配合逐算子偏移，使重放时的随机舍入继续变化。
4. 通过明确的 `include` / `keep` 名称模式保护精度边界。选中可训练权重、不支持的卷积或存在歧义的共享模块时，会拒绝转换。
5. 使用合成张量验证原生计算路径、缓存往返、输入梯度、动态随机舍入和更换输入后的重放行为。

本更新不附带应用数据、模型检查点、未公开的工作负载配置或应用实验成绩。

## 适用范围

支持标准 `nn.Linear`、无分组且步长为 1、无填充的 1×1 `nn.Conv2d`，以及受限的 `nn.MultiheadAttention` 自注意力：无 dropout、无 attention/padding mask 或因果提示，不返回注意力权重（传入 `need_weights=False`）。MHA 按整体转换，保护其子层会保留整个 MHA。

普通卷积、归一化、softmax 和残差状态不会因此变为 FP4。转换后的投影接收 BF16/FP32 激活、输出 BF16，内部矩阵运算和输入梯度使用现有原生 FP4 路径。需要更新的权重继续使用原训练模式。

自定义函数式投影、绑权/共享参数、分布式、二阶梯度和动态形状需要单独接入。新模型仍须检查输出和梯度：只保留输入输出为 BF16，不能保证内部量化后仍保持应用需要的评分或梯度方向。

图捕获会占用显存池及主机元数据，可能抵消部分权重节省。应分别测普通执行、捕获和重放，并区分框架分配与整卡占用。逐样本子图过多时，可以在应用回调中有界分批，但要核验目标计算仍一致。不能仅根据位宽承诺固定倍数的速度或总显存收益。

## 使用方式

先按仓库首页安装并执行后端验证，再运行：

```bash
python examples/frozen.py
python -m unittest discover -s tests -p test_frozen.py -v
```

新项目主要提供三个部分：模型、完整目标函数、精度边界清单。完整 API 示例见 [英文说明](frozen.md) 和 [合成示例](../examples/frozen.py)。

`capture_frozen` 的预热会执行真实前反向，但不会更新参数。重放会自行清零固定梯度缓冲；图存活期间不要使用 `zero_grad(set_to_none=True)`，也不要替换参数或缓冲。输入形状、类型、设备、是否需要梯度及模块训练模式必须固定。重放及外部优化器使用原调用流，不支持并发捕获。捕获前丢弃旧计算图，需要长期保存输出时用 `.clone()`。

输入会复制到独立固定缓冲。需要端到端梯度时，应捕获完整可微目标，而不是把此对象插入外部计算图当作普通子模块。纯推理使用 `backward=False`。可训练参数的优化器更新由调用方在图外执行。

缓存使用不可变模型版本或检查点摘要作为 `model_fingerprint`。其余参数另外恢复；缓存和 `.sha256` 文件属于本地模型资产，不应随代码自动发布。新项目保留一次小规模数值与资源验收，已验证的底层打包、缓存和重放实现无需重新编写。
